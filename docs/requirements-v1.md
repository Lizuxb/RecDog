# 第一版需求工作稿

状态：第一版需求规格；可进入原型设计与技术可行性验证。未决项均标记为技术验证或后续版本，不阻塞原型启动。

产品名称：**RecDog**，中文名：**听录**。界面布局与交互见[产品设计文档](product-design-v1.md)。2026-11-02 的布局确认及页面批注已纳入下文；记录需求不表示现有原型已实现。

## 定位与平台

- 单人使用的个人访谈、会议及带格式模板的审讯记录工具。
- 第一阶段 Windows 安装版与便携版；提前定义跨平台项目格式，为未来 macOS、手机客户端保留空间。
- 手机客户端留待后续开发，初步定位为随身录音、转写、查看与简单修改；复杂模板编辑和正式文档整理以电脑端为主。手机端技术栈另行评估，不要求与 Windows 使用相同语言或界面框架，不纳入第一版交付。
- 单机优先，无强制账号、云同步、第三方插件 SDK 或项目加密；备份由用户手动执行。

## 项目与数据

- 一个项目作为普通目录保存，不使用专用扩展名；目录内保留项目索引、多个逻辑成员目录、录音、模板、文档和版本等源文件。项目目录可直接复制备份和迁移，成员可自定义名称并具有稳定内部编号。若未来需要单文件分享，可在目录格式稳定后另行增加打包功能。
- 项目保存位置由用户选择；模型保存在独立目录供多个项目复用，不随项目重复打包。便携版设置默认保存在程序旁的可写目录；API 密钥不写入项目文件。
- API 密钥默认仅在本次运行期间使用；用户主动选择“记住密钥”时使用 Windows 凭据保护能力，不明文写入普通设置文件。便携版换电脑后可能需要重新填写密钥，项目和其他设置不受影响。
- 支持每段录音关联一个文档实例，也支持用户明确将多个录音关联到同一文档。
- 录音统一以 MP3 保存，默认保留，可手动删除并提示无法重新转写的后果。
- 自动保存草稿；每次确认最终记录生成可查看和恢复的版本。
- 支持项目全文搜索，并至少按成员、录音和说话人筛选。

## 录音与转写

- 开始、暂停、继续、结束、快捷键、自动保存属于第一版；重新打开使用最近已保存数据，不另做专项崩溃恢复。插入标记与补录后置。
- 单次连续录音至少四小时；过程中持续保存，不等录音结束才写入。
- 录音结束或意外停止后再次点击录音，新建音频文件并保留上一份，两份归入同一项目成员目录，不覆盖或自动拼接。只有仍处于中断前的项目、成员和原文档，且未更换模板时，才默认续写原目标；用户可主动新建文档。每段文字分别关联实际来源录音，不能仅按同名文档猜测关联。
- 正常暂停后继续属于同一份录音；暂停期间不采集声音，并明确显示状态。
- 在线转写断网时继续本机录音和编辑，保留尚未转写的音频；网络恢复后提示补转历史或只处理后续，不自动切换服务。补转结果先进入未分配内容，由用户指定写入位置。
- 录音期间关闭窗口，提供“结束录音并保存后退出”“取消关闭”；不默认后台录音。正常退出保存已录内容。
- 保存与重开统一以自动保存的数据为准：录音持续写入，文档草稿、转写及录音来源关联持续自动保存；重新打开直接加载最近已保存的数据，不增加恢复向导或专项崩溃恢复功能，不承诺找回未保存内容，不设专项崩溃丢失窗口。重开不自动开始录音，由用户手动开始。自动保存仍须避免正常读取半写入数据或破坏上一次已保存状态，具体实现待技术验证。
- 第一版同一时间只进行一场录音；录音期间切换项目时，提示“结束并保存后切换”或“取消”。
- 支持麦克风、电脑播放声音、两者混合录音，以及导入 WAV、M4A 等常见音频；项目保存为 MP3，不主动删除外部原文件。
- 以中文为主，准确率优先；按设备能力选择策略，实时展示临时文字，最终结果可延迟数秒。
- 用户可从列表下载受支持的本机模型，或指定已有模型目录；需验证兼容性并显示资源需求。也允许主动配置在线转写服务。
- 在线转写采用服务商预设、密钥填写与独立连接测试；选择时显示语言、说话人和时间定位等服务能力，与 AI 文档整理分别配置。
- 每段录音记录模型/服务、版本（如服务可提供）和参数，允许不同录音使用不同提供方。
- 区分临时结果与可编辑文字；人工修改过的段落不能被后台结果覆盖。
- 临时文字后续修正原位更新，不随录音目标切换移动；新内容写入当前录音目标。服务无法可靠区分修正与新增时，保留待处理结果，不猜测覆盖或重复追加。
- 说话人分离可关闭；支持 A/B/C 标注、角色预设和自定义命名、段落改标、合并和拆分，不承诺真实身份声纹识别。
- 支持笔记本内置麦克风及系统可用的外接单麦克风，用户可选择录音输入设备；内置麦克风无需额外购买设备。支持一个多通道录音设备提供的独立声道，可辅助标记说话人；多个独立 USB 麦克风同时采集后置。多通道能力仍需按设备和驱动验证，不承诺所有设备兼容。
- 点击转写片段只跳转音频位置，不自动播放；用户播放时同步高亮文字。
- 转写失败不影响录音、已有文字或文档编辑；保留输入与结果，弹窗提示，可换服务重试或关闭转写后手动输入。
- 算力不足时优先保证录音完整和文档可编辑；显示可估计的转写落后时长，允许暂停转写、录完再处理或由用户主动更换在线服务，不丢弃待转写音频，不自动上传。

## 文档与 AI

- 支持导入 DOC/DOCX，日常默认导入 DOCX；导入旧版 DOC 时可先转换为 DOCX，保留原文件并显示兼容报告。导入后转换为软件自己的内部文档模型进行编辑和保存，不要求在软件内直接编辑 Word 文件或嵌入完整 Word 编辑器；最终导出 DOCX，不提供第一版旧版 DOC 导出。支持普通段落、表格单元格与内容控件，标识可填写位置；复杂对象尽量保留，无法可靠保留的内容必须明确报告。DOC 转换依赖及其便携部署方式待技术验证。
- 核心编辑、模板填写与 DOCX 导出不依赖安装 Word 或 WPS；旧版 DOC 转换为单独兼容能力，转换组件不可用时提示用户先转换为 DOCX，不阻断核心功能。
- 模板兼容性验收涵盖纸张大小、页边距、页眉页脚、页码及表格跨页设置，以导出的 DOCX 内容、表格结构和主要格式变化不大为目标，不要求无损往返；软件内不要求与 Word 分页逐像素一致，不支持的设置必须报告。
- 显式选择录音目标，后续文字追加到该位置；切换不移动已经写入的内容。
- 编辑光标与录音目标分离：普通点击只移动编辑光标，明确执行“设为录音目标”才切换写入位置，并持续高亮当前目标。
- 转写结果首次写入文档时，使用当时用户选中的录音目标，不按音频讲话时间回溯分配。例如 A 目标期间说的话尚未返回，用户切换到 B 后结果才返回，则写入 B。用户允许跨目标拆分内容，不强制保持整句归属；不自动移动已写入内容。
- 录音目标被删除时继续录音，转写进入“未分配内容”；用户重新选择目标后自行决定是否补入暂存文字。更换模板创建新的文档实例并保留旧文档。
- 录音时实时写入可编辑文档草稿；用户确认后生成正式版本，作为 AI 整理和正式导出的默认输入。确认不阻碍录音中填写。
- 录音期间允许确认正式快照，录音继续且后续文字进入工作草稿；已确认版本保持原样，下次确认生成新版本。
- 支持字体大小、粗体、斜体、下划线、对齐、换行、撤销/重做、表格单元格、基本列表。
- 支持创建空白文档、增删表格行列、合并及拆分单元格；第一版不提供复杂嵌套表格、浮动文本框等高级排版的创建编辑能力。导入模板中已有复杂对象仍按兼容性报告与尽量保留的规则处理。录音目标因编辑被删除时，后续结果进入未分配内容。
- 第一版导出 DOCX。Markdown 导入/导出后置，包括 AI 派生结果的 Markdown 导出。
- 用户编辑后的转写或文档保留段落级录音来源关联，不承诺逐字对应；纯手动新增段落显示“无关联录音”。AI 派生结果第一版不提供逐句音频定位。
- 用户确认过的修订文字本身就是最终记录，不依赖 AI 才能导出。
- AI 可选，支持用户配置 OpenAI 兼容文本接口的地址、密钥和模型；只处理用户指定的最终记录，做语言清理、重点提炼和总结，保存独立派生结果。
- 支持可保存的提示词模板，支持独立结果与逐项差异审核，不静默替换最终记录。
- 在线处理前明确告知数据上传并由用户主动启用；可选录音提示和确认记录保存时间、操作者与提示状态，不代替法律判断。

## 界面、模板管理与保存（2026-11-02 确认）

- 产品采用现代简约、黑白灰与少量强调色、轻量细线的工具界面。参考图片的简约视觉语言，不采用网站首页式大标题、宣传区域或装饰性布局。
- 主工作台采用“左侧项目与成员、中间可编辑文档、右侧转写、底部录音控制”；右侧可收起，为文档腾出空间。
- 中间文档在独立容器内通过鼠标滚轮上下滚动；长文档不能撑高整个窗口或被裁切而无法访问。顶部编辑工具栏和底部录音控制保持可用。用户已报告当前原型文档无法滚动，登记为待修复问题，不视为已经验收。
- 文档模板的导入统一放在“模板库”；移除左栏“导入录音或文档”这一混合入口。录音导入仍属于项目/成员下的录音操作，不放进模板库；具体入口位置见产品设计建议。
- 支持从空白文档自建模板，或修改导入文档后另存为可复用模板。第一版模板库支持名称、预览、重命名、复制和删除，不增加复杂拖拽设计器。
- 文档模板默认保存在当前项目中；跨项目通过导入或复制复用，复制项目目录时一并迁移。文档模板与 AI 提示词模板保持不同用途和入口。
- “版本记录”和“正式版本”统一收进“设置 → 版本记录”，按当前项目、成员和文档定位版本；移除主工作区标题旁与左侧栏的重复版本入口。主界面的“确认最终记录”继续保留，创建正式版本的语义不变。
- 编辑工具栏增加明确的“保存”按钮，与既有每 2 秒自动保存并存。保存用于保存当前草稿，不等于确认正式版本、导出 DOCX 或另存为模板。界面显示保存中、已保存、保存失败及最近成功保存时间；失败时提供重试。
- “未分配内容”保留为转写暂存能力，并补充通俗说明：已转写但尚未写入文档指定位置的文字。原录音目标删除、历史补转等场景可产生此类内容；用户选择目标并主动插入后才写入文档，不自动补入、不重复插入。用户本次提出的是含义咨询，不解释为要求删除该功能。
- 产品设计文档应包含功能位置图、主操作流程图和异常处理流程，说明每个功能的入口、作用和结果。

## 能力边界

录音采集、转写、说话人分离、文档解析/编辑、AI 处理、导出和项目存储应独立定义责任。只实现第一版所需适配器，不提前构建第三方插件系统。

## 性能要求（指标待验证）

- 最低配置目标：Windows 10/11 64 位、8GB 内存，保证录音、文档编辑、自动保存、DOCX 导入/导出和在线转写的基础体验；推荐 16GB 内存用于本机转写与说话人分离。
- 本机实时转写按具体模型、CPU、可用内存和是否启用说话人分离分别验证和标注，不把“支持离线”解释为所有设备都能实时。
- 四小时录音及长文档场景纳入性能验收，不能只测试短录音。
- 录音、转写、文档编辑、搜索、项目保存应避免相互阻塞；算力不足时优先录音完整与文档编辑，转写允许落后并明确显示状态。
- 内存不应因音频累计时长而无限增长；音频应持续写入，转写、文档展示和索引采用有界处理。实现方式须由技术验证确定。
- 项目对用户表现为一个可复制的目录；不要求每次自动保存都重新打包全部历史音频。长录音下的保存速度、磁盘峰值及已保存数据的完整性属于技术验证重点。
- 文档和设置默认每 2 秒自动保存；自动保存不能阻塞录音、转写或编辑，具体写入策略待技术验证。

## 尚未解决

- 已确认实时填充草稿与确认正式版本的区别；首次写入的转写结果按当时选中的目标分配，不按讲话时间分配。
- 在线实时转写已完成首轮官方文档调研，候选仍需中文实录验证；不能假设任意文本 API 都支持音频。
- 项目大小、MP3 编码参数和本机模型的最低硬件要求待技术验证；不另设专项崩溃恢复窗口。
- 项目目录结构、索引格式和源文件命名待原型验证；默认自动保存频率已确定为 2 秒。
- 具体性能验收设备待选定，目标系统已确定为 Windows 10/11 64 位；本机模型实时性不能仅凭支持离线运行而承诺。
