# RecDog（听录）产品开发计划

日期：2026-11-02。状态：仓库骨架已初始化；构建未验证，风险 MVP 与产品功能未实施。

## 目标与约束

以 [需求规格](requirements-v1.md)、[产品设计](product-design-v1.md)、[技术方案](technical-design-v1.md) 和 [ADR](adr/) 为依据。先验证关键风险，再实施完整 V1。MVP 不代表删除已确认的首版功能，也不是可发布产品。

- Windows 单机桌面应用，安装版和便携版；无 Web 服务器、账号或同步平台。
- 单次录音至少四小时，录音持续写盘，文档和设置默认每两秒自动保存。
- 人工修订不被后台转写覆盖；正式版本不可变；AI 生成独立派生文档。
- 本地 Git `main`；暂不设置远程或许可证。需求/设计与代码一起版本管理。
- 保留原资料目录；新仓库文档是后续开发依据。静态原型属于参考资料。

## 阶段 0：仓库与工程骨架

实施：复制 docs、GLOSSARY 和 prototype；建立 README、忽略规则、三层 .NET 工程与解决方案；测试目录保留用途说明。Desktop 引用 Core 和 Infrastructure；Infrastructure 仅引用 Core；Core 不依赖 WPF。暂不安装未经验证的候选依赖。

验证：检查项目引用、XAML/XML、文档本地链接及忽略规则；在装有 .NET 10 SDK 的 Windows 上执行根 README 的 restore/build/run，再从干净检出重复。当前本机无 SDK，构建与启动保持未验证，不允许标记阶段完全通过。

## 阶段 1：风险验证 MVP

详细步骤见 [验证清单](validation/mvp-checklist.md)。依次验证模板/编辑器、音频归档、转写与目标规则、保存迁移，最后并行长测。每个探针独立可运行并保留运行说明，结果写成实际报告；未验证性能不写成支持承诺。

界面：使用最小 WPF 窗口验证中文输入、表格、长文档滚动和录音目标，不先制作完整工作台。处理层：只实现探针所需的 DOCX 映射、录音编码、转写和 SQLite 适配，不引入插件框架。

退出条件：真实模板和样本完成验证；四小时持续采集通过；保存迁移和目标/人工编辑规则通过；确定可用编辑器、编码链路与首个转写组合。失败项先记录原因、替代选择和复测结果，经评审后再进入产品开发。

## 阶段 2：项目、文档模型与保存基础

实施：Core 定义稳定 ID 的项目、成员、录音、文档节点、目标与段落来源模型；Infrastructure 实现 SQLite 格式版本/迁移、单写入协调、事务和文件安全发布；Desktop 提供项目导航、草稿与保存状态。保存按钮与两秒周期走同一保存路径，保存期间新修改不能误标为已保存。

验证：领域测试覆盖目标删除、来源和版本规则；集成测试使用真实 SQLite 与临时项目目录，覆盖创建、重开、迁移、复制、保存中继续编辑和写入失败。失败保留上次成功状态，来源与对应内容一致，不阻塞采集/UI。

## 阶段 3：手动工作闭环

实施：AudioHost 负责麦克风/系统声/混合采集与暂停，FFmpeg 编码持续写盘；结束再录产生新录音 ID。文档模块实现模板库、空白文档、基本编辑、正式快照、DOCX 导入导出及兼容报告。Desktop 按产品设计实现三栏布局、独立正文滚动、保存/录音状态、模板入口、结束保存后退出或切项目。

验证：无 AI、无在线服务完成创建项目 → 模板/空白文档 → 录音 → 手动编辑 → 确认 → DOCX 导出；按技术方案 A01—A04、A11—A15、A21、A22 核验。确认不停止录音，后续只更新草稿；暂停不采集，退出不后台录音；DOCX 在 Word/WPS 检查结构与主要格式。此阶段是首个可试用闭环。

## 阶段 4：转写与音频定位

实施：AsrWorker 独立承载本机模型，在线服务使用独立适配器；统一转写事件进入 Core 的目标绑定和修订规则。首次返回按当前目标写入，后续修正留在原绑定，人工修改保护优先。前端展示转写状态、积压、说话人、未分配内容与来源；点击只定位，播放同步高亮。

验证：可控事件覆盖 A05—A10、A16、A17、A20；重复、乱序、跨录音事件不会污染文档。删除目标继续录音，明确插入才补入；断网、模型失败继续录音编辑，不自动上传/切服务。在线模型能力以真实样本实测，不套用文本 AI 配置。

## 阶段 5：完整 V1 能力

实施：补齐设置内版本查看/恢复、表格增删/合并/拆分与撤销、中文搜索筛选、模型下载/目录验证、设备配置；可选 AI 使用指定正式版本，提示词与派生结果独立保存，提供差异审核；旧 DOC 转换是独立可选组件。

验证：A13、A15、A17—A19、A23；一二字中文查询不漏查；恢复不改写历史；AI 不覆盖原始正式版本；取消/失败不破坏输入。密钥不写项目，记住密钥只用 Windows 用户保护；在线上传须主动启用；无 DOC 转换器仍可使用核心 DOCX 功能。

## 阶段 6：发行与验收

实施：自包含 win-x64 目录生成安装版/便携包；补齐依赖与模型版本、许可/校验、支持设备/系统及用户说明。此时添加 Windows CI，执行恢复、构建及真正存在的测试项目。

验证：完整技术方案 A01—A25；四小时录音、转写、保存和长文档并行，观察内存趋势、保存延迟和 UI；注入断网、设备移除、模型退出、磁盘不足及导出中断；已保存数据不损坏。无 SDK、无独立运行时、无 Word/WPS 的目标机完成核心流程；安装器卸载不删除用户项目/模型。所有门槛有证据才标记 V1 可交付。

## 协作、提交与变更

初期单代理顺序推进，节省重复上下文与协调成本。不为“省 token”默认开多个代理。边界稳定后才拆分 DOCX、音频或独立评审；同一模块由一个实现者修改。任务说明只带必要资料、输入输出与验收用例。

每个独立可验证改动提交一次，提交信息说明行为与目的；不要把样本、密钥或本机模型纳入提交。`.gitignore` 只是兜底，提交前仍检查暂存内容。远程和许可证待用户另行决定。
